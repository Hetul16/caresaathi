# 19. Deployment: getting a public link for the judges

Judges need a link they can open. Three ways, from fastest to most solid. Everything uses synthetic data only (CLAUDE.md, rule 8).

| Way | Time | Good for | Weakness |
| --- | --- | --- | --- |
| A. Tunnel from your own laptop | 15 minutes | Trying it on a phone today, a backup demo | Dies when the laptop sleeps or the tunnel stops |
| B. One cheap server with Docker | 1 to 2 hours | A permanent home | Costs a few dollars; needs a domain or the server's address |
| C. Managed platform, paid | 2 to 3 hours | No server to look after | Three services plus a database to set up |
| D. Four free plans (D-70) | about 1 hour | **The submission link** | The API sleeps after 15 idle minutes; nothing is guaranteed to stay free |

Recommendation: **D** for the submission link, **A** as a backup during judging. **B** if this outlives the hackathon.

## What is deployed

Four parts, however they are hosted: `api` (FastAPI, runs the database migrations on start), `web` (Next.js, forwards `/api/*` to
`api`), a Postgres database with the baseline schema and roles, and somewhere to keep uploaded files. There is no MinIO, no worker
and no hosted backend service.

Way B puts all four in one Docker Compose on one machine, with `caddy` for the public address and HTTPS, and files on a volume. Way
D puts each with a different free provider and files in an S3 bucket.

## D. Four free plans (the submission link)

The website on Vercel, the API on Render, the database on Neon, the uploads in Cloudflare R2. Checked against each provider's own
pricing page on Nov 1, 2026; free tiers move, so read them again before trusting the numbers (D-70). **No application code changes**:
the browser still talks only to the website's own origin, which forwards `/api/*` to the API, so the refresh cookie stays first-party.

The deployment is private until submission day (D-69). `PUBLIC_LAUNCH.md` is the list for opening it.

1. **Database (Neon, free).** New project, Postgres 17, same region you will pick for the API. From `psql` with the owner connection
   string, in this order: `db/schema.sql`, then `db/roles_and_grants.sql` with the four placeholder passwords replaced, then
   `db/seed_drug_families.sql`. Do this before the first deploy: the migrations build on this baseline and will fail without it.
   Free plan: 1 GB, and the compute suspends after 5 idle minutes and wakes on the next query.
2. **Files (Cloudflare R2, free).** A bucket named `caresaathi` and an S3 API token with object read and write. The endpoint is
   `https://<account id>.r2.cloudflarestorage.com`, without the bucket name. Free: 10 GB and no egress charge.
3. **API (Render, free).** New &rarr; **Blueprint**, point it at the repository; `render.yaml` describes the service. Paste the values it
   asks for -- the four connection strings, the R2 keys and endpoint, the Meta key, `SITE_GATE_TOKEN`, and `PUBLIC_BASE_URL` and
   `CORS_ORIGINS` set to the **website's** address, which you will know after step 4 (set them then and redeploy). `JWT_SECRET` and
   `TOKEN_PEPPER` are generated by Render. The image runs `alembic upgrade head` before uvicorn, so deploying migrates.
4. **Website (Vercel, free).** Import the repository, set **Root Directory** to `frontend`, and add two environment variables, both
   server-side and neither prefixed `NEXT_PUBLIC_`: `BACKEND_URL=https://caresaathi-api.onrender.com` and `SITE_GATE_TOKEN`, the same
   value as the API's. Then go back and fill in step 3's two addresses.
5. **Stay private while you test.** Vercel &rarr; Settings &rarr; **Deployment Protection** &rarr; scope **All Deployments**, method
   **Vercel Authentication**. Free on Hobby; Password Protection is not. Only you, signed in to Vercel, can open the site -- including on
   your phone. The API has the gate from step 3, which is the half a stranger could otherwise reach.
6. **Check it:** `python backend/scripts/launch_check.py https://<your website>`. Two of its checks can only pass once the site is
   public, which is the point of `PUBLIC_LAUNCH.md`.

`.env.render.example` shows the shape of every value. Keeping the API awake during judging: ping `/healthz` every 10 minutes from any
free scheduler. That is 744 hours a month, inside the 750 the free plan allows for one service.

## B. One server with Docker

1. Get a small Linux server (2 GB memory is enough) and a name pointing to it (an `A` record). Install Docker and the Compose plugin. Open ports 80 and 443.
2. Copy the repository to the server (`git clone https://github.com/Hetul16/caresaathi.git`).
3. `cp .env.production.example .env.production` and fill it in. Make secrets with `python3 -c "import secrets; print(secrets.token_urlsafe(48))"` for `JWT_SECRET` and `TOKEN_PEPPER`. Set `PUBLIC_BASE_URL=https://your.domain` and `SITE_ADDRESS=your.domain`. Put the Meta key in `META_API_KEY`. Keep `SPEND_LIMIT_USD` at your budget. The server refuses to start on an `https` address while a development secret or a default `change-me` password is still set.
4. Also create a file named `.env` next to it with `POSTGRES_PASSWORD`, `S3_ACCESS_KEY` and `S3_SECRET_KEY` (compose reads these for the database and validates the MinIO names). Use the same `POSTGRES_PASSWORD` inside `DATABASE_URL_ADMIN`.
5. Start the database alone first and set the role passwords. The roles are created with placeholder passwords, so change them before anything else uses them:
   ```
   docker compose up -d db
   docker compose exec db psql -U postgres -d caresaathi -c "ALTER ROLE caresaathi_app PASSWORD '<app password>'" -c "ALTER ROLE caresaathi_auth PASSWORD '<auth password>'" -c "ALTER ROLE caresaathi_worker PASSWORD '<worker password>'" -c "ALTER ROLE caresaathi_readonly PASSWORD '<readonly password>'"
   ```
   Use the same passwords in the three `DATABASE_URL_*` lines of `.env.production`.
6. `docker compose --profile app up -d --build`. The first start builds both images and applies migrations 0002 to 0010.
7. Open `https://your.domain`. Sign up, press "Load the demo family", and walk through the demo path in `docs/06-testing-demo.md`.
8. Check: `https://your.domain/trust` loads without signing in; a doctor link and an Emergency Card link open in a private window; the model name on `/trust` is the live one.

Update later with `git pull && docker compose --profile app up -d --build`. Back up with `docker compose exec db pg_dump -U postgres caresaathi > backup.sql`.

## A. Tunnel from your laptop

1. Install `cloudflared` (no account needed for a quick tunnel). Start the backend and `npm run dev` or `npm run build && npm start` as usual.
2. `cloudflared tunnel --url http://localhost:3000` prints an `https://something.trycloudflare.com` address.
3. For doctor links and Emergency Card links to carry that address, restart the backend with `PUBLIC_BASE_URL` set to it. Because that is an `https` address, set real values for `JWT_SECRET` and `TOKEN_PEPPER` first, or the backend will refuse to start (this is intended).
4. The address changes each time the tunnel restarts, so do not put it in the submission.

## Before you submit the link

`PUBLIC_LAUNCH.md` is the ordered version of this, with the three switches that make the deployment public. The checks:

- Signing up works from a phone on mobile data, and the microphone prompt appears (this needs HTTPS).
- A second browser cannot open another family's patient (try the patient address while signed in as a different user).
- `SPEND_LIMIT_USD` is set, and `python scripts/spend.py` (in `backend/`) shows what has been used.
- The repository is public and contains no `.env` or `.env.production` (check with `git ls-files | grep env`).
- Say plainly on the page that all data is fictional (the "Synthetic patient" marker is already shown).

## Limits to know about

- The spend ledger is a table (D-68), so it survives a restart and counts the same whichever copy of the API spends. The `$`
  figure in `python scripts/spend.py` is the real total.
- With way B, uploaded files live on the `storage` volume and `docker compose down -v` deletes it. With way D they are in R2,
  and the API container keeps nothing: a free Render service has no persistent disk at all.
- Browser text-to-speech depends on the voices installed on the viewer's device, so Hindi and Marathi read-aloud may fall back to a default voice on some phones.
